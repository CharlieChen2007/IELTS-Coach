# WorkBuddy 部署交接：最终锁定发布版

**本轮发布以《最终发布与原样部署.md》和根目录 release-manifest.json 为准。** WorkBuddy 只负责原样部署，不改代码、不重建 dist、不重新生成发布清单。先运行 `node scripts/release-integrity.mjs verify`，成功后再启动；若平台无法按原包部署，报告阻碍交回 Codex。

本次交付为完整 Node24 网站，含三个写作算法、四科前端、同源 API、自动迁移的 SQLite 数据库和本地教学素材。请部署整个工程，不要只上传 `dist` 到静态托管，也不要使用历史 Worker 入口。此前确认的听力、口语界面、校园营地、搭子广场、互助单、小队挑战、词汇工具和动画均保留。阅读练习左右栏独立滚动是本版的正确行为。

验证码旧云应用当前不可用。必须在平台激活当前应用并启用短信/邮箱服务，再设置 `WORKBUDDY_PUBLISHABLE_KEY`；可选 `WORKBUDDY_CLOUD_ENDPOINT`、`WORKBUDDY_OAUTH_RELAY_BASE_URL`。填写激活返回的公开值，不是 API Secret。配置由 `/cloud-config.js` 运行时下发，改后重启服务即可，不能再把旧域名写死进前端。未激活前不可声称真实收码已通过。

## 1. 先配置服务器，再发布公网地址

1. 解压进入含 `package.json` 的目录，使用 **Node.js 24.0 或更高版本**，建议 Node 24。
2. 使用随包的预构建 `dist`，直接执行 `node scripts/start.mjs`；此运行路径不依赖 node_modules。`npm ci` / `npm run build` 仅供后续开发使用，会使当前锁定清单失效，不能在本轮部署时执行。此工程使用 `node:sqlite`，不需要手工安装 MySQL，也不要用 Vite preview 代替后端。
3. 在托管平台的**服务器环境变量/Secret**处填写下面的设置。不要把密钥写入前端、`VITE_*`、聊天、Git 或交付压缩包。
4. 让平台反向代理转发到启动端口，绑定 HTTPS 公网域名，再验收。浏览器麦克风需要安全上下文；语音识别与朗读还取决于浏览器、系统和相应服务的可用性。

部署前可运行 `npm run verify:ai` 验证本包的 AI 接口合同。此命令使用临时数据库与替身上游，不读取真实密钥、不产生模型费用；它不代替发布后的真实 API 验收。写作请求超时上限为 180 秒，平台代理的请求时限也应允许完成此类长请求。

自动评测队列的浏览器复验为 `node scripts/verify-speaking-browser.cjs`。此项需先 `npm ci`，并用 `CHROMIUM_PATH` 指定已安装的 Chromium/Edge 可执行文件；测试只替换外部供应商，不产生模型费用。

| 变量 | 用途与填写方式 |
| --- | --- |
| `HOST` | 填 `0.0.0.0`，允许平台代理访问容器。 |
| `PORT` | 服从平台注入的端口；仅平台未注入时自行设置，例如 `4192`。 |
| `PUBLIC_ORIGIN` | 最终公网源地址，例如 `https://ielts.example.com`，不含路径或 `#/...`。不要保留示例域名。 |
| `IELTS_DATA_DIR` | 平台**持久化挂载卷**上的绝对目录。数据库、录音对象等保存在这里；不能指向重新部署就清空的临时目录。 |
| `DEEPSEEK_API_KEY` | DeepSeek 官方 API Key。由服务器发送请求，浏览器不会获得密钥。 |
| `DEEPSEEK_BASE_URL` | 默认 `https://api.deepseek.com`，通常无需修改。 |
| `DEEPSEEK_MODEL` | 默认 `deepseek-flash`。写作 Task 1 需要可接收图片的模型，换模型后必须重新验收图像输入。 |
| `TENCENT_APP_ID` | 腾讯云主账号 APPID，用于口语评测。 |
| `TENCENT_SECRET_ID` / `TENCENT_SECRET_KEY` | 具备口语评测权限的子账号凭据。 |

写作新入口默认每天每账号 40 次成功批改，可用 `WRITING_AI_DAILY_LIMIT` 调整；缓存不扣、失败退还。一次批改可能包含多个审题、读图及有限格式重试，本站批改次数不等于供应商请求数或 Token 费用。旧通用代理仍兼容并共享额度。听/读深度复盘默认每天每账号 10 次，可用 `STUDY_COACH_DAILY_LIMIT` 调整。腾讯调用量按实际分段请求计，不等于整场模考次数；可用 `SOE_SITE_DAILY_LIMIT` 和 `SOE_VISITOR_DAILY_LIMIT` 限制用量。

根目录 `deploy.env.example` 仅供参考，不自动加载。推荐在平台控制台设置变量。Windows 本机的加密凭据文件不会随包迁移；线上必须在服务器单独配置腾讯凭据。

一个部署实例共用一份服务端数据库。若平台不支持持久化磁盘，请先解决数据存储再公开验收；不能把临时文件系统当作稳定数据库。SQLite 方案适合本次单实例团队 Demo，不应直接横向扩成多实例各自一份数据库。

## 2. AI 与评分的边界

| 功能 | 处理方式 |
| --- | --- |
| 自由对话、追问、表达反馈 | DeepSeek 读取文本转写。 |
| 口语综合反馈 | DeepSeek 结合本人服务端作答及可信评测证据生成学习建议。文本维度参考与腾讯百分制指标分开展示；尚无经校准的雅思换算，不生成四维雅思总分。 |
| 发音及不标准词定位 | 腾讯 SOE 处理真实音频；原有自动上传队列保留。 |
| 写作逐句批改、改写、升级范文 | DeepSeek；Task 1 连同题图提交。原稿、批改快照、二稿与历史沿用现有功能。 |
| 听力、阅读错因深入分析 | 从本人已提交的服务端作答取证据，由 DeepSeek 补充分析和练法。原有逐题解析仍可独立查看。 |
| 识别、录音、播放 | 浏览器语音识别、麦克风录制和系统朗读；不把原始音频发送给 DeepSeek。 |
| 标准答案、正确数、成绩换算、记忆调度、积分与匹配 | 仍由题库和程序处理，模型不改写事实。 |

未配置密钥时，已有练习、题库、规则解析和校园功能可运行，界面会如实提示 AI/发音评分的可用情况。包内使用替身上游验证接口合同，不代表已经消耗真实付费 API 完成验收。

## 3. 发布前必须实际点通

- 用普通浏览器打开公网地址，确认不需要 ChatGPT、Codex 或 WorkBuddy 工作台账号。应用内昵称入口是网站自身的入口。
- 两个独立浏览器进入两个用户；分别做听力、阅读和写作，交卷后立刻切科目再返回，确认记录互不串用且最终结果保存。
- DeepSeek 配置后，完成一次自由对话、一份有可信音频证据的口语报告、Task 1 图片批改、Task 2 批改及听/读错因分析。口语综合反馈沿用完整三部分门槛：Part 2 原始陈述至少 60 秒、各部分有足够的原始英文转写；快速演练和手工校正转写不冒充完整模考。检查结果来源和失效提示。
- 腾讯配置后录一段英语，确认录音结束后自动评测、报告中出现腾讯百分制结果及需要改进的词。没有腾讯证据时不得出现伪造的发音分，也不能把腾讯百分制线性换算成雅思分数。
- 进入/退出演示模式，确认学习数据、校园数据和普通账号隔离；搭子约练、互助单一次回复、诊所语音复练、组队周任务可继续操作。
- 重启服务后再次查看记录；重新部署后复查持久化目录没有被清空。部署前备份已有数据库与录音对象。
- 桌面和手机宽度检查四科、校园分类切换、右侧二级工具、动画和滚动条；检查真实手机的麦克风权限与浏览器兼容性。

### 账号说明

本项目保留现有昵称/浏览器会话账号入口和演示空间。不同同学可访问同一个公网服务，但仅输入同一昵称不等于已实现跨设备账号找回。不要在展示中承诺尚未接入的邮箱验证码、密码找回或统一校园身份认证。
