# IELTS Coach · 最终验收发布版（2026-11-11）

交给 WorkBuddy 部署请先看 [WorkBuddy 部署说明与可复制提示词](WorkBuddy部署说明.md)。本包交付完整前后端；公网部署需要服务器 Secret、HTTPS 域名和持久化数据目录。不要只发布静态网页。

本轮以 WorkBuddy「写作批改一次成功版」为基线，修复 Task 1 报告内边距、三科进场时机和 Task 2 首稿画像兼容问题。详见 [最终验收记录](最终验收记录-2026-11-11.md) 与 [原样部署规范](最终发布与原样部署.md)。历史修复交接供追溯；实际线上版本以 `/api/release` 与本地 release-manifest.json 比对为准。阅读做题和解析的左右栏独立滚动是正确行为。

## 从这里开始

使用 Node.js 24.0 或更新版本。解压整个文件夹，Windows 双击「启动整合版.cmd」。也可以在项目根目录运行 `node scripts/start.mjs`。浏览器打开 [小组版学习首页](http://127.0.0.1:4192/?demo=1#/auth)，用昵称进入后，点击顶栏的「演示模式」即可载入当前昵称的学习记录。退出演示会返回原账号数据。若端口被占用，以启动窗口显示的地址为准。

本包内含成品网页、完整源码、数据库建表脚本及本地音频。首次运行会自动创建 SQLite 数据库。安装同一台机器上的个人作业版时，两份工程可分别启动，各自使用自己的数据目录。压缩包不包含 API Key、个人数据库或用户录音。

## DeepSeek 接入

服务器统一使用 `DEEPSEEK_API_KEY`，默认模型 `deepseek-flash`，可通过 `DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL` 调整。腾讯口语评测仍使用独立腾讯凭据。口语对话与报告、写作精修、听力与阅读的错因深入分析使用同一 DeepSeek 适配层；不会把原始录音发给文本模型。写作 Task 1 含题图，替换模型时必须确认图像能力。

所有模型请求在服务端发送，设有输入校验、限额和失败提示。标准答案、判题、积分和排位仍按程序计算。未配置模型时，现有题库、规则解析和校园功能仍可使用。真实付费调用须在 WorkBuddy 配置 Secret 后按部署说明验收，不能用“配置存在”代替“调用成功”。详细范围见 [AI 接入验收与边界](AI接入验收-2026-11-10.md)。腾讯发音保留百分制，未经校准不换算为雅思分数或四维总分。

## 本次交付

本包从 WorkBuddy 交回版接回，修复阅读与写作账号串用、提交切页丢同步、交卷未进入主站记录、互助与诊所路由、跟读重复记账和录音刷新丢失等问题。阅读与写作已分别接入真实提交快照、主站历史、错题/复练及校园任务。动效、按钮反馈和手机页签采用同一套规则。

本次继续恢复卡片逐层上移、缩放及插画进场，补齐阅读书本与写作稿纸钢笔主视觉。听说读写仍各自保留原来的练习、题库和报告；口语、阅读、写作按一级分类与二级工具整理。通用词汇移到独立「词汇积累」，阅读中从原文收藏的词保留在「阅读生词」。

二级工具已与一级分类放在同一工具栏最右侧，空间不足时自然换行。校园活动分类与练习分类共用外观，选中底板采用同一套滑动与变色过渡。内嵌页面高度由未缩放的布局尺寸上报，避免动画中测到偏小高度而产生第二根整页滚动条；听力结果的分数与分母组合居于圆环中心。

[验收覆盖与运行边界](REVIEW-2026-11-10.md) 记录了本轮发现、复测方法和外部服务配置。当前包可在本机直接运行，重新部署时请发布整个包的前端与后端，并在部署环境设置域名和凭据。

## 从学习首页到校园营地

桌面侧栏的校园区和手机菜单提供「营地」「排行榜」「寻找搭子」「考试经验」。营地里的活动导航提供互助单、小队挑战、校级目标和积分明细。首次演示建议点顶栏的「演示模式」。可体验已有练习、邀请、求助、组队以及营地养成的账号。用完点「退出演示」回到原账号。

- **营地**　点亮门口的灯，查看营地等级与校园猫，用自己获得的饲料兑换猫粮，再选择库存中的食物投喂。成员共看本校成长进度。
- **排行榜**　查看本周总榜、四科专项榜和我的流水。营地经验、饲料和排行榜积分各有自己的用途。
- **寻找搭子**　浏览需求卡，按需填写六题画像，发布自己的需求、处理邀请，成为搭子后可约同一道练习。
- **考试经验**　浏览本校考场档案，补充考试体验，发布备考心得，给其他同学的经验标记「有用」。内置的演示内容用于展示操作流程。

## 一个人演示

- 从「校园营地 → 搭子广场」邀请同学。接受后点卡片上的「一起练」，选科目、练习和时间。搭子确认后，双方各自进入同一道练习，回到约练页交换心得。一个人演示时可以选择模拟搭子，代为确认并查看示例心得。
- 从「校园营地 → 互助单」认领一道题，提交一条回复。回复收起为回执，下一步由发单同学复练、对照作答并标记解决。在大厅勾选「我参与的」可回看进度。真人互助单支持两个账号分别演示这两种角色。
- 从「口语陪练 → 学伴互助 → 口语诊所」选择要练的问题，预约时段，用麦克风作答后可对比练前、练后原声。同一分类的「同校互助单」用于留言求助。昵称和空闲时段在「个人空间 → 个人资料 → 校园资料」修改。
- 从「口语陪练 → 同伴练习 → 双人模拟考」点击「开始人机模拟」，轮流当考生和考官。真人配对与邀请房间也可以从这里打开。第二级的「备考小组」单独管理组队与周任务。
- 从学习首页的「查看写作批改示例」可直接看原稿、逐句批注和改写。浏览示例不写入个人成绩或积分。

## 每日语料

正式入口在「口语陪练 → 跟读训练」。第二级页签：**今日跟读 / 语料库 / 跟读记录**；学习首页「日常积累」里的「每日语料」卡片是同一个入口的快捷方式。地址 `#/subject/speaking?view=daily`（另可 `daily-library`、`daily-history`）可直接打开、刷新、收藏。

- **今日跟读**　7 天 × 3 条学术示范语料，支持整段/逐句/意群停顿/影子跟读、0.75×–1.1× 变速。录音或点「示例音频」后提供本地练习反馈；示例操作不增加个人学习记录，本地声学指标不等同于腾讯 SOE 发音评分或正式雅思成绩。
- **语料库**　按天浏览全部 21 条，含中文理解提示与可迁移表达。
- **跟读记录**　历史报告与分数曲线。

学习记录按账号写入 `daily_learning` 表（迁移 `modules/speaking/drizzle/0008_daily_learning.sql`），接口为 `GET/PUT /api/daily/shadow`；普通账号与演示空间互相隔离，原始录音不上传、不入库。详细说明见 `每日语料接入说明.md`。

## 独立词汇积累

侧栏「学习工具 → 词汇积累」与首页同名卡片打开 `#/vocabulary`，提供 800 个高频词、主题词库、卡牌翻面、四档记忆调度、听写及复习记录。词表每页 24 词，搜索与筛选仍覆盖完整词库，避免窄屏长列表超过页面高度上限。学习进度沿用原账号数据；旧 `#/subject/speaking?view=vocab` 链接兼容进入同一工作区。词汇不再列入口语功能页签。阅读原文里的生词收藏仍保留在「阅读精读 → 学习工具 → 阅读生词」。

## 听力演示

| 分段 | 主题 | 题型 | 题数 |
| --- | --- | --- | --- |
| Section 1 | 二手家具电话咨询 | 笔记填空 | 7 |
| Section 2 | 夏令营员工职责 | 匹配 | 5 |
| Section 3 | 地外生命证据 | 流程图选词 | 5 |
| Section 4 | 学习者坚持性研究 | 表格填空 | 5 |

1. 进入「听力精练」先看到训练首页。可试听十秒原声、点选分段材料或继续上次草稿。作答页显示播放器、已答题数和全宽答题卡。未交卷答案按账号及分段暂存在当前浏览器。
2. 每段独立交卷。服务端判分后展示正确数、漏答与逐题解析。展开播放器下的原文，点一句即可从该句回听。
3. 在「本段错题本」修改错因，选择重听原题或同类题复练。连续两次答对即可掌握。重做整段会重新开始该段练习；历史报告仍可回看。
4. 「题型训练」首次进入即可查看六大类、十三个细分题型。四类使用原声分段，其余九类各有一道校园原创专项及本地合成录音。提交后才显示正确率，专项成绩按题型单独保存。总站的「历史记录」「分数曲线」「错题本」也能查看听力记录，听力成绩按本段实际题数展示。
5. 从听力顶部「学伴互助」发布互助单。从作答页进入时会带上当前分段，可选具体题目和本人作答。从报告完成有效纠错可获得校园积分，加入小队后可查看周进度。

素材使用范围依听力组交接说明为非商业教学演示。四段原声、样题与逐字稿来自其提供的 IELTS 官方机考样题材料，公开发行前需确认素材授权或替换。

## 其他科目与校园功能

口语支持完整模考、快速演练、自由对话、双人模拟、评测报告和学伴互助。阅读与写作也从科目训练首页进入，打开主练习或专项训练后开始作答。每一科的导航都有「学伴互助」。小队挑战按四人四科的本周完成格数排名。校级目标按深圳大学的英语成绩转换要求展示练习证据和下一项训练。

## 切页与加载的动效

主内容采用统一的上移、轻微缩放与卡片错落进场：普通内容约 540ms，插画约 620ms，相邻块间隔约 65ms。顶栏、侧栏和分类导航保持稳定；异步模块就绪、二级切换、返回旧视图都会触发对应内容进场，离屏卡片在滚到时播放。动画由同一运行时管理，避免叠加整页与子卡片位移、反复强制布局或持续逐帧轮询。减少动效偏好会直接呈现内容。业务表单与 iframe 文档不会因播放动画被重建。

一级分类与二级切换的选中底板约 340ms 平滑滑动，文字同步过渡。窗口缩放或布局换行时会直接校准位置，避免底板从旧位置跨出页面。减少动效偏好同样关闭这类位移。

## 开发与数据

- 安装项目依赖用 `npm ci`，开发预览用 `npm run dev`，重新构建用 `npm run build`。
- `src/pages/SubjectPage.tsx` 是四科共用的页面壳，`ListeningPanel.tsx` 连接听力练习台与总站，`src/listeningIntegration.ts` 负责本站报告及错题适配。
- 浏览器端播放器和题型组件在 `public/listening/`，完整题库和判分逻辑在 `modules/listening/`。浏览器从同源 `/api/listening/` 获取该账号可见的题面与结果。Node 静态目录使用 `dist/`。
- 本机独立数据目录默认为项目根目录的 `.data/`，可通过 `IELTS_DATA_DIR` 指定。服务端按账号在该浏览器的会话保存已交卷作答、错题、复练和校园记录。本机演示模式使用昵称和邮箱进入。
- 腾讯口语评测依赖服务端配置。Windows 启动器可使用当前用户此前保存的加密凭据；其他机器在服务端配置 `TENCENT_APP_ID`、`TENCENT_SECRET_ID`、`TENCENT_SECRET_KEY`。听力不依赖腾讯云口语评测。
- 历史 Worker 入口不适用于本次 Node24 写作算法。本版必须按 Node 服务部署；以下为旧版绑定记录，勿作为本版部署步骤： `ASSETS`、D1 `DB` 和私有 R2 `BUCKET`。建库顺序为 `modules/speaking/drizzle/*.sql`、`modules/campus-social/schema.sql`、`modules/campus-social/buddy.sql`、`modules/campus-social/buddy-portraits.sql`、`modules/campus-social/buddy-meets.sql`、`modules/campus-social/growth.sql`、`modules/campus-clinic/clinic.sql`、`modules/campus-clinic/places.sql`、`modules/listening/schema.sql`、`modules/listening/type-results.sql`。验证码需重新激活当前 WorkBuddy 云应用，填入本版运行时公开配置；不再使用旧站点绑定。

## 验收

```sh
node scripts/verify.mjs
node modules/listening/verify.mjs
node modules/reading/verify.mjs
node scripts/verify-writing.mjs
node modules/campus-clinic/verify.mjs
node modules/campus-social/verify-growth.mjs
node modules/campus-social/verify-daily.mjs
node modules/campus-social/verify-meet.mjs
```

浏览器检查用 `node scripts/check-motion.mjs`，设置 `BASE_URL` 为正在运行的测试服务，`CHROMIUM_PATH` 为本机 Chromium 或 Edge 可执行文件。接口检查会创建临时数据库。

`node scripts/check-single-scroll.mjs` 用真实占宽的滚动条检查动画中、动画后及窗口变化时的内嵌文档尺寸，并覆盖词表分页、词条弹窗与写作题库展开。`node scripts/check-circle-alignment.mjs` 检查分数环、题号和头像等对齐；未设置 `BASE_URL` 时可使用隔离构建与 SQLite 运行此项。

写作 Task 1 / Task 2 在未配置 AI 时会生成有逐句锚点的基础规则反馈。真实 AI 精修需要服务端 `DEEPSEEK_API_KEY`。旧的 `AI_API_KEY`、`OPENAI_API_KEY` 不再作为模型凭据回退。原稿、建议采纳、二稿对比与历史记录可独立使用。
