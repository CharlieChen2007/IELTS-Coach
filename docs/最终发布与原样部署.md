# 最终发布与原样部署

本次以「IELTS-Coach-写作批改一次成功版-2026-11-11.zip」为基线。Codex 负责代码，WorkBuddy 仅负责运行和部署。禁止在部署阶段编辑源码、重建前端、调整评分算法、删除现有数据库或覆盖服务端密钥。

## 锁定和校验

交付含预构建 dist，可直接使用 Node.js 24 或更高版本运行 `node scripts/start.mjs`，无需安装前端依赖或再次构建。

`release-manifest.json` 记录全部交付源码、文档、服务端和构建资源的 SHA256。运行 `node scripts/release-integrity.mjs verify` 必须输出 verified=true；新增、缺失、修改发布目录内文件都会失败。最终服务器启动前自动校验；校验失败或清单缺失时停止启动。`/api/release` 只返回本次发布身份及启动时校验结果，不返回密钥、账号或文件内容。

部署前、部署后各执行一次完整性校验。不要重新生成清单掩盖修改。若平台要求代码调整，停止并将原因交回 Codex，生成新包后再部署。

Codex 会在公网对全部静态 dist 文件逐一比对 SHA256：`node scripts/verify-online-release.mjs https://实际公网地址`。唯一例外 `/cloud-config.js` 由服务器环境动态输出，只允许三项公开云配置；工具会单独解析并校验其安全形状，不执行远端 JavaScript，也不把它误报为静态字节一致。公网校验为只读，不消耗 AI 配额。

## 数据库和密钥

项目包含自动迁移的 SQLite 数据库与录音对象存储。`IELTS_DATA_DIR` 必须指向平台持久化卷；默认的项目内 `.data` 只适合本机或平台明确保留项目目录的场景。生产仅运行一个写入实例，录音与数据保存在同一 studio.sqlite 中。先确认、备份现有数据库，再把新服务绑定到原有持久化目录；不要用空数据库替换已有数据。备份包含账号数据，不得发布到静态资源中。

保留当前有效服务端环境变量和密钥，包内仅有 deploy.env.example。HOST=0.0.0.0，PORT 使用平台分配的端口，PUBLIC_ORIGIN 使用实际公网域名。不要把真实环境文件复制进 dist、ZIP、聊天或版本库。

验证码需要当前 WorkBuddy 云应用的公开配置与已启用的短信/邮箱通道；DeepSeek 与腾讯 SOE 需要对应服务端凭据。配置缺失时页面如实提示，不能使用固定验证码或伪造模型分数替代。配置状态通过现有 status API 检查，不在日志输出凭据。

## 上线验收

确认无需登录 ChatGPT/Codex 即可访问；首页和听说读写均可进入；阅读原文、题目可独立滚动；Task1/Task2 提交、报告、二稿和社区首稿画像保持联通；演示与真实学习空间隔离。

使用测试账号保存一条练习，重启同一个服务后再次读取同一记录，并核实实际持久化卷设置。普通进程重启只能证明数据库落盘，不能代替容器替换或持久化卷证据。记录最终网址、releaseId、两次完整性校验结果和数据库持久化证据；若任何项未验证，应明确说明。
