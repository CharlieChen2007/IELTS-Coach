### 4. AI 能力（需要如实说明的边界）

交接包说明写的是「WorkBuddy 云端上线可直接调用，超量后暂停，可能需要配置 API 保底」。核对后的实际情况：

- 当前部署环境**没有** `DEEPSEEK_API_KEY`，也没有检测到任何 WorkBuddy / OpenAI 兼容网关环境变量；`api.deepseek.com` 裸请求返回 401。
- 因此 `/api/ai/chat` 在未配置时返回结构化 `AI_NOT_CONFIGURED`（HTTP 503），前端会给出友好提示，**不会崩溃、不会白屏**。
- 但**游客全流程仍可用**：包内 Task 2 批改在缺少 `host.evaluate` 时走内置本地估分引擎，四维估分、逐句建议、二稿对比、示例报告都不依赖外部 LLM；草稿与题库全部可用。
- 服务端已做成「多变量名探测」：只要运行环境提供 `DEEPSEEK_API_KEY` / `AI_API_KEY` / `OPENAI_API_KEY`（以及可选 `AI_BASE_URL` / `DEEPSEEK_BASE_URL` / `OPENAI_BASE_URL`），**无需改代码**即可启用逐句 AI 精修。
- 每账号每日上限默认 40 次（`WRITING_AI_DAILY_LIMIT`），超量自动暂停 AI 精修，本地功能照常，对应「超量后会被暂停服务」。
- 配置方式写在 `deploy.env` 注释里，取消注释填 Key 即可。密钥只在服务端读取，浏览器拿不到。
