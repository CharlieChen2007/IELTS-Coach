### 方式 A：让我配（最快，1 分钟）

把 key 发我，我在服务器写进 `.env` 并重启、再做一次真实调用验证。注意：key 会出现在聊天记录里，用完建议在 DeepSeek 控制台**轮换一次**。

### 方式 B：你自己在服务器上配（推荐，key 不经过聊天）

```bash
cd /workspace/ielts-coach-refined

# 1) 写入服务端本地 .env（已在 .gitignore 中，不会进包）
printf 'DEEPSEEK_API_KEY=%s\nDEEPSEEK_MODEL=deepseek-flash\n' 'sk-你的key' > .env

  --dir /workspace/ielts-coach-refined --install-cmd "" --start-cmd "node scripts/start.mjs"
```

## 三、这次部署额外修的一个问题

**现象**：交卷后顶部出现「备份尚未完成，本机记录已保留」黄色提示，但接口其实返回 200，刷新后数据也在。

**原因**：交卷瞬间阅读模块连续多次上报进度，主站把同一版本的状态发了两次 29 KB 的 `PUT`。浏览器对 `keepalive` 请求有 64 KB 全局配额，第二个请求被挤住挂起，20 秒后超时中止，触发失败提示。数据没丢，是提示误报。

**修复**（三处，最小改动）：

| 文件 | 改动 |
| --- | --- |
| `src/iframePersist.ts` | 同一版本已成功落库就不再重复上传；失败回报前先判断该版本是否已被写成功 |
| `src/iframePersist.ts` | `keepalive` 只用于 < 16 KB 的请求，大请求走普通 `fetch`（主站 window 不销毁，不需要 keepalive） |
| `public/reading/assets/reading-host.js` | 收到确认时按「版本不低于当前」清除提示，避免版本前进一格后提示残留 |

**复测**：交卷后 20 秒内提示条始终为 0，`PUT /api/reading/state` 只发一次且返回 200；清空浏览器本地阅读数据后刷新，「1 已完成」仍从服务端恢复。
