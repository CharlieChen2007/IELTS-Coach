# 口语模块 · 双人模考与备考小组

## 本机打开

安装 Node.js 22.13 或更高版本。在项目目录双击「启动口语协作预览.cmd」，打开 http://127.0.0.1:4176/#campus 。也可运行：

```sh
node scripts/build-worker.mjs
node scripts/preview.mjs
```

用普通窗口和无痕窗口设置两个不同的昵称。一个建邀请房，另一个输入房间码，或两人都选快速匹配。每轮由考官开题，考生录音并提交。考官可在计时内发送追问，提交后回听并给出优点、改进点和复练建议。两轮交换角色后，双方各获得一次口语完成记录。这是按轮次共享录音的双人练习。每轮限时两分钟，上传有一分钟网络宽限。数据和音频保存在本地 `.preview-data`，重启可恢复。分开设备使用麦克风时，须在总网站的同一 HTTPS 域名下访问。

## 交给总站前端

集成后的口语入口为 `/campus.html`，小组入口为 `/campus.html#campus-team`。附带的示例宿主同时支持 `/#campus`。总网站可将这两个入口加到口语导航，或在总站自己的页面分别挂载组件：

```js
import { mountSpeakingPair } from './pair-speaking.js';
import { mountTeamProgress } from './team-progress.js';

const stopPair = mountSpeakingPair(pairElement);
const stopTeam = mountTeamProgress(teamElement, {skill:'speaking'});
// 切换路由时清理轮询与录音。
stopPair();
stopTeam();
```

两组件均使用同源 cookie。先用 `GET /api/campus/me` 检查身份，尚未建立昵称时发同源 JSON `POST /api/campus/session`，参数为 `{nickname}`。已接入托管账号的用户按账号归属，公开访客按浏览器身份归属。演示昵称不代表已验证的学校身份。总站若有自己的登录，在服务端的 `identity(request)` 使用总站可信的用户标识。浏览器不得自行指定一个用户 ID 来读取他人进度。嵌入页加载 `style.css` 的基础样式及 `team-progress.css`、`pair-speaking.css`，保留 `#campus-team` 作为回到小组的目标。

小组支持 1–4 人。按相同考试月份和目标分、至少一个共同空闲时段匹配，或用邀请链接加入。进度只向当前组员显示，按北京时间周一到周日统计。每人每科每周目标 1 次，显示实际完成次数。听、读、写页面也可挂同一组件，将 `skill` 改为 `listening`、`reading`、`writing`。本包实际接通口语的单人模考、已保存的自由对话和双人模考，其他科的完成处理留给相应模块接入。

## 交给总站后端

1. 客户端请求 `/api/campus/*` 时分发到 `server/campus.mjs` 的 `handleCampus(request, env, {json, readJSON})`。保留浏览器的同源校验、音频二进制请求体以及响应的 Set-Cookie、Range 标头。现有 `server/api.mjs` 展示接法。账号身份由可信网关注入，预览服务器会剥离外部传入的身份标头。
2. 数据库按编号执行 `drizzle/*.sql` 中尚未应用的迁移。已有备考小组会由 `0007_campus_team_space.sql` 迁入常规学习空间。使用项目自己的迁移编号和部署配置。SQLite/D1 存房间、小组和进度；音频使用私有对象存储绑定 `BUCKET`，回听接口校验房间成员。原声训练的腾讯云密钥继续放在服务端。
3. 某科的正式答卷或练习已经持久化后，服务端调用 `awardTeamProgress(env, campusUserId, skill, completionId, completedAtMs)`（由 `server/campus-teams.mjs` 导出）。同一用户、学科、完成编号仅计一次，传入原始完成时刻。成功后前端可发 `window.dispatchEvent(new Event('campus:progress'))`，其他成员的看板也会在轮询时更新。
4. 样例以 `dist/server/index.js` 完整运行；总网站已有自己的首页、API 或 Worker 时，合并相应路由及资源即可。随包未包含任何生产站点 ID、密钥、录音或学生数据。
